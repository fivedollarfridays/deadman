# Objective

A link to the public board unfurls as a preview card on LinkedIn, Slack and X,
without changing a byte of the JSON board that existing clients read.

# Context

`GET /` returns the board as `application/json` to every caller. Link
unfurlers (LinkedInBot, facebookexternalhit, Slackbot, Twitterbot) read Open
Graph tags from HTML, so a JSON body gives them nothing and the link renders
as a bare URL. The ops board watcher and the test suite read the JSON with no
`Accept` header, so the JSON response is a contract that must not move.

# Implementation Plan

1. RED: content negotiation. Known unfurler user agents and an `Accept` that
   prefers `text/html` get HTML; no `Accept`, `*/*`, `application/json`, or a
   tie get JSON.
2. RED: the HTML carries og:title, og:description, og:url, og:image and
   twitter:card, with factual README wording, and escapes every board string.
3. RED: `GET /` JSON body and headers are identical to today's for curl-like
   and urllib-like clients.
4. RED: `GET /og-card.png` serves a 1200x630 PNG as `image/png`, ships as
   package data, and serving it records no sweep.
5. GREEN: `deadman.preview` module; two call sites in `service.make_app`.
6. A checked-in script (`scripts/render_og_card.py`) renders the card.

# Acceptance Criteria

- [x] The HTML view carries og:title, og:description, og:url, og:image and twitter:card
- [x] curl with no Accept header, or Accept: application/json, gets exactly today's JSON (tests prove it)
- [x] og:image is served by the service at a stable path, 1200x630 PNG
- [x] The card is generated by a script checked into the repo
- [x] Board strings in the HTML are escaped
